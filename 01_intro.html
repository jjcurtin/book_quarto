1  Quarto Workshop: What Is Quarto?

1.1 Why are we here?

By the end of this hour you will be able to:

  • Explain what Quarto is and how it works with R and RStudio
  • Write a report that mixes text and R code
  • Render it to a self-contained file and publish it online
  • Turn the same kind of document into a slide deck
  • Write a manuscript with citations and cross-references

You’ll build along with me the whole hour, with a few Your turn moments to try a step on your own.

1.2 What is Quarto?

Quarto is a free, open-source publishing system.

You write one plain-text file (a .qmd) that mixes:

  • Text, written in markdown
  • Code, in R or Python
  • A few options at the top, written in YAML

Quarto turns that file into a finished document:

  • Reports (HTML, Word, PDF)
  • Slide decks
  • Manuscripts and journal articles
  • Posters, websites, dashboards (these are not covered today)

1.3 R, RStudio, and Quarto

Three tools, three different jobs:

Tool What it is Its job
R (or Python) A programming language Runs your code: data, models, figures
RStudio An IDE Where you write code and documents
Quarto A publishing system Turns your .qmd into a finished document

You use them together:

  • write a .qmd in RStudio,
  • render it from the terminal, and
  • Quarto has R run your code and builds the document around the results.

1.4 What happens when you render

quarto render report.qmd

  • An engine runs your code chunks: knitr for R, Jupyter for Python
  • Your numbers, tables, and figures are woven into the text
  • Pandoc converts the result to the format you asked for

The engine runs your code in a fresh session,

  • not in your RStudio console.
  • Remember this; it matters in the next unit.

1.5 Why use Quarto?

The old way With Quarto
Copy numbers from the console into Word, then they drift out of date when the data change Text and code live together; numbers are computed every time you render
Rebuild the same figure for the report, the slides, and the paper One source, many formats
Type citations by hand and renumber figures when you reorder them Citations come from a .bib file; figure and table numbers update themselves
“How did I get this result?” Rendering re-runs everything from scratch, so the document is the record
Binary files that Git can’t compare Plain text that works with Git

1.6 A few quick notes

Quarto is its own program.

  • Like Git, you run it from the terminal, and every command starts with quarto.
  • It works the same whether you edit in RStudio, Positron, VS Code, or Jupyter.

It is not just for R.

  • If your project uses Python, you can use Quarto the same way.
  • Code chunks just say {python} instead of {r}.

Coming from R Markdown?

  • Quarto is its successor.
  • Most of what you know carries over, and your .Rmd files still work.

1.7 Source vs. output

File What it is What you do with it
report.qmd The source Write and edit it; commit it to Git
report.html The output Read and share it; never edit it by hand

Quarto rebuilds the output from scratch every time you render, so any edits you make to the HTML will be overwritten.

To change the output, change the source and render again.

We have:

  • Defined Quarto as a publishing system, separate from R and RStudio
  • Seen what happens when you render
  • Seen why it beats copy and paste for reports, slides, and papers
