Author

John J. Curtin, PhD

Introduction to Quarto

Quarto lets data scientists write reports, slide decks, and papers as plain-text documents that combine writing, code, and results. When the data or the analysis changes, you re-render, and every number, figure, and table updates itself. This book is a hands-on introduction, built around a single running example: 170 years of ice records for Lake Mendota, which grow from an empty file into a published report, a slide deck, and a paper.

How this book is organized

The book has two parts.

Basic has five units, covered live in a one-hour, hands-on workshop. They follow the life of a typical project: a report, then slides for a talk, then a paper.

  • Unit 1 introduces Quarto and how it turns a .qmd file into a finished document.
  • Units 2–3 build a report and publish it online.
  • Units 4–5 reuse that report to make a slide deck and a paper.

Advanced units go beyond the live hour and are for you to work through on your own afterward. They pick up where the workshop leaves off, using the same report.qmd, slides.qmd, and paper.qmd you built. To see what a new feature does, add it to your own file and render it (or publish it) yourself.

  • Advanced markdown: more ways to format text, including links, images, tables, math, and callouts.
  • Chunk options and figures: control what each code chunk shows, and size, caption, and arrange figures.
  • Tables: turn data frames into tables that look good in HTML, Word, and PDF.
  • Advanced slide formatting: columns, themes, code on slides, and more for your decks.
  • YAML in depth: more settings for reports, decks, and papers, and where YAML can live.
  • Quarto projects and paths: what a _quarto.yml file does, and how your code finds its files.
  • Reusing code across products: keep one copy of your analysis code for a report, slides, and a paper.
  • Git with Quarto projects: which Quarto files to commit and which to ignore.

Each Basic unit also has a companion slide deck, published on Posit Connect Cloud. These are the decks we present live. The Advanced units are in the book only.

Before the workshop

Please finish these steps before the workshop so we can spend our time together on Quarto itself. They take about 15 minutes.

This setup builds on the Git workshop. It assumes you already have:

  • Git installed (on Windows, this gave you Git Bash)
  • A GitHub account
  • An SSH key connecting your computer to GitHub

Type every command below in a terminal: Terminal on macOS or Linux, Git Bash on Windows, or the terminal inside RStudio.

Step 1: Install Quarto

Download the installer for your operating system from https://quarto.org/docs/download/ and run it.

RStudio comes with its own copy of Quarto, but please install Quarto separately anyway. The separate install works in any terminal, and it lets you control which version you have. You won’t break anything: RStudio will use your installed copy automatically.

When the installer finishes, close any open terminals and restart RStudio so they can find Quarto.

Step 2: Check your Quarto version

Open a new terminal and run:

quarto --version

You need version 1.9 or higher. Earlier versions can’t publish to Posit Connect Cloud from the terminal, which we will do in the workshop.

If you don’t see a version number of 1.9 or higher:

  • command not found: Quarto isn’t installed, or the terminal can’t find it yet. Re-run the installer, then open a new terminal and try again.
  • A version lower than 1.9: your terminal is finding an older copy of Quarto, often one installed for an earlier course. Run which quarto to see where that copy lives. Then download the current installer from the link above, run it, and check the version again in a new terminal.

For a fuller diagnosis, quarto check reports which version of Quarto you are running and whether it can find R and Python.

Step 3: Create a Posit Connect Cloud account

Posit Connect Cloud is a free service for sharing documents online. We will publish a report and a slide deck to it during the workshop.

  1. Go to https://connect.posit.cloud/
  2. Click Sign Up
  3. Choose to sign up with GitHub, using the GitHub account you already have

The free plan is all you need. If you already have an account, you can skip this step.

Step 4: Create your workshop repo on GitHub

During the workshop you will build a small project about ice cover on Lake Mendota. Make a home for it on GitHub now.

In your browser, signed in to GitHub:

  1. Click + (top right) → New repository
  2. Name it mendota_ice
  3. Choose Public or Private; either works
  4. From the Add .gitignore dropdown, choose the R template
  5. Click Create repository

Don’t skip the .gitignore. It tells Git to ignore the clutter that R and RStudio create (like .Rhistory and .Rproj.user/). It also gives the repo its first commit, so when you clone it, git push and git pull work right away.

Step 5: Clone the repo to your computer

On your new repo’s page, click the green Code button, select the SSH tab, and copy the address.

In your terminal, move to the folder where you keep your GitHub repos. We used ~/github in the Git workshop; use your own folder if it’s different. Then clone the repo, pasting your own address:

cd ~/github
git clone git@github.com:your_username/mendota_ice.git

Move into the new folder and look around:

cd mendota_ice
ls -a
.  ..  .git  .gitignore

You should see the .gitignore you created on GitHub, plus the hidden .git folder that holds the repo’s history.

Step 6: Download the data, references, and citation style

Our report will use 170 years of ice records for Lake Mendota, and our paper will cite them in APA style. Put a copy of the data in a data folder inside your repo. Put the reference file (refs.bib) and the APA style file (apa.csl) at the top of your repo.

Stay in your mendota_ice folder. Copy the four commands below (use the copy button at the top right of the box), paste them into your terminal, and press Enter:

mkdir data
curl -fsSL -o data/mendota_ice.csv https://raw.githubusercontent.com/jjcurtin/book_quarto/main/data/mendota_ice.csv
curl -fsSL -o refs.bib https://raw.githubusercontent.com/jjcurtin/book_quarto/main/refs.bib
curl -fsSL -o apa.csl https://raw.githubusercontent.com/jjcurtin/book_quarto/main/apa.csl

mkdir makes the data folder. Each curl command downloads one file. If all goes well, none of the commands prints anything.

Check that the files arrived:

head -3 data/mendota_ice.csv
head -1 refs.bib
grep "<title>" apa.csl
winter,year,ice_days
1855-56,1856,118
1856-57,1857,151
@dataset{magnuson2026,
    <title>APA Style 7th edition</title>

If you see an error instead, make sure you are in your mendota_ice folder (pwd shows where you are), then paste the commands again. If mkdir says the folder already exists, that’s fine; just run the three curl lines.

That’s it. You’re ready for the workshop. We will start from this folder.

How to use this book

Quarto is best learned by doing. As you read, follow along in your own mendota_ice repo: write each file in RStudio (or any editor) and render it yourself. Everything builds one running example, so the report, slides, and paper you create grow right alongside the book.

We render and publish from the terminal (Terminal on macOS or Linux, Git Bash on Windows, or the terminal in RStudio), not with buttons in RStudio. The commands are short, they work the same in any editor, and you will see exactly what Quarto is doing.

A few conventions to know:

  • Commands you type appear in shaded code blocks, with the output shown just below them.
  • Your turn boxes are short challenges to try on your own before moving on.

The source for this book lives on GitHub; corrections and suggestions are welcome.
